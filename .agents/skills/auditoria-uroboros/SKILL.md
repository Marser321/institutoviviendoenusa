# Auditoría Uroboros

Esta skill implementa un proceso de auditoría cíclico y estricto diseñado para proyectos de alto rendimiento. Se basa en el concepto de **Uroboros** (la serpiente que se muerde la cola) para representar la mejora continua y la auto-corrección.

## 1. El Proceso Uroboros (Pasos Obligatorios)

Cada auditoría DEBE seguir estos pasos en orden secuencial. No se permite saltar fases.

| Fase | Nombre | Acción |
| :--- | :--- | :--- |
| **Fase 1** | **Ingesta Total** | Leer `AGENTS.md`, `STATE.md`, `CONTEXT.md` y el código afectado. |
| **Fase 2** | **Pensamiento Lateral** | Cuestionar las premisas. ¿Hay una forma radicalmente distinta de resolver esto? |
| **Fase 3** | **Escrutinio Estricto** | Validar contra las "Reglas Duras" del repositorio (TypeScript, Tailwind, Auth, etc.). |
| **Fase 4** | **Detección de Entropía** | Identificar deuda técnica, redundancias o posibles regresiones. |
| **Fase 5** | **Propuesta de Variantes** | Ofrecer al menos 2 variantes (A: Conservadora, B: Disruptiva). |
| **Fase 6** | **Cierre de Ciclo** | Actualizar el registro de aprendizaje para mejorar la próxima auditoría. |

## 2. Pensamiento Lateral Aplicado

Al auditar, no te limites a buscar errores de sintaxis. Aplica estas heurísticas:
- **Inversión**: ¿Qué pasaría si hiciéramos exactamente lo contrario?
- **Eliminación**: ¿Qué parte del código es realmente innecesaria?
- **Analogía**: ¿Cómo resolvería este problema un sistema biológico o una infraestructura urbana?
- **Restricción**: Si no pudieras usar la librería X, ¿cómo lo harías?

## 3. Auto-Mejora Continua

Después de cada auditoría, debes registrar lo aprendido en `/home/ubuntu/skills/auditoria-uroboros/references/learning_log.md`. 
- ¿Qué patrón de error se repitió?
- ¿Qué solución lateral fue la más efectiva?
- ¿Qué regla del `AGENTS.md` fue la más difícil de cumplir?

## 4. Estándares de Salida

Toda auditoría debe entregarse en un bloque Markdown estructurado con:
1. **Resumen Ejecutivo**: Estado de salud del código (0-100).
2. **Hallazgos Críticos**: Violaciones directas de las reglas duras.
3. **Variantes Uroboros**: Propuestas de mejora con pros y contras.
4. **Acción Inmediata**: El siguiente paso técnico más pequeño y efectivo.

> "La perfección no se alcanza cuando no hay nada más que añadir, sino cuando no queda nada por quitar."
